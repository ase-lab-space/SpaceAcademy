## 宿題:なぜプルアップの方が主流なのか

### 結論

決定的な理由が1つあるわけではなく、**いくつかの実務的な理由が重なって**プルアップの方がよく使われています。授業では「唯一の正解を当てる」よりも、学生が思いついた理由を歓迎しつつ、以下の観点を補足する形が良いでしょう。

### 理由の例

1. **断線・接触不良に対して安全側(フェイルセーフ)になりやすい**
   配線が外れたり接触不良を起こすと、入力ピンは(内蔵/外付けの)プル抵抗側の電圧に落ち着きます。多くの制御盤や非常停止ボタンでは「異常時は安全な状態(≒待機状態)に倒れてほしい」という設計思想があり、プルアップ+アクティブLow(押す/異常時にLowになる)の組み合わせは、配線トラブル時に「押されていない(＝正常)」側に安全に倒れる設計と相性が良い場面があります。
2. **多くのマイコン・ロジックICで、内蔵プルアップの方が歴史的に手軽だった**
   TTL/CMOSロジックの歴史的経緯から、内蔵プルアップが標準搭載されているチップが多く、アクティブLow(0のときに意味がある)という信号の慣習が広く定着しました。I2Cのように、規格そのものがプルアップ前提になっている通信方式もあります。
3. **GNDを共有基準にした配線の方が、ノイズに強く配線しやすい場面が多い**
   多くの回路でGNDは基板全体に張り巡らされた共通の基準面になっていることが多く、スイッチの片側をGNDに落とす配線(プルアップ+スイッチでGNDに落とす)は、電源ラインに落とす配線より実装上扱いやすいことがあります。

### 授業での伝え方の例

- 「配線が外れて浮いてしまったら困るのはどっち? 動いてほしくないのに動いてしまう方が困る?それとも、動いてほしいのに動かない方が困る?」と、フェイルセーフの観点から水を向けると考えやすいです。
- 唯一絶対の正解を求めすぎず、「複数の理由が重なっている」ことを伝えるのがポイントです。

## 確認課題の解答例(コード)

### 課題1:ボタンを押している間だけLEDを光らせる

```py
from machine import Pin
import time

button = Pin(16, Pin.IN, Pin.PULL_DOWN)
led = Pin(15, Pin.OUT)

while True:
    if button.value() == 1:  # 押されている
        led.value(1)
    else:
        led.value(0)
    time.sleep(0.05)
```

### 課題2:ボタンを押している間だけモーターを回す

```py
from machine import Pin
import time

button = Pin(16, Pin.IN, Pin.PULL_DOWN)
gate = Pin(13, Pin.OUT)

while True:
    if button.value() == 1:  # 押されている
        gate.value(1)
    else:
        gate.value(0)
    time.sleep(0.05)
```

いずれも、`led`/`gate`の変数名と対象が違うだけで、ロジックは同一です。学生がここに自力でたどり着けたら、「出力の書き方を変えずに、入力で判断を挟むだけで良い」という感覚が掴めている証拠です。第1回の「LEDもモーターも同じ操作だった」という学びと、今回の「入力を判断に挟む」という学びが、ここで一本につながります。
